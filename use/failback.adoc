= 使用 NetApp Disaster Recovery 故障回复到源站点
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/use/


[role="lead"]
灾难解决后，从灾难恢复站点回切到源站点以恢复正常操作。您可以选择用于恢复的快照。

*需要 NetApp Console 角色* 需要超级管理员、灾难恢复管理员或灾难恢复故障转移管理员角色才能执行此任务。link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-disaster-rec-roles.html["了解NetApp Disaster Recovery中的用户角色和权限"^].link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["了解所有服务的NetApp Console访问角色"^].



[[about-failback]]
== 关于故障恢复

在故障恢复中，NetApp Disaster Recovery 会在反转复制方向之前将任何更改复制（重新同步）回原始源工作负载。此过程在关系故障切换到目标后开始，涉及以下步骤。Kubernetes 工作负载遵循与 VMware 工作负载相同的顺序；特定于 VMware 的详细信息在括号中注明。

* 对恢复的站点执行合规性检查。
* 刷新在恢复站点中标识的每个 vCenter 集群或 Kubernetes 集群的发现信息。
* 在目标站点上，停止受保护的工作负载（对于 VMware，关闭并注销虚拟机），并卸载卷。
* 打破原始源上的SnapMirror关系以使其可读/写。
* 重新同步SnapMirror关系以逆转复制。
* 在源上启动受保护的工作负载（对于 VMware，开启并注册源虚拟机），并在源上挂载卷。




[[before-you-begin]]
== 开始之前

对于 VMware 工作负载，如果使用基于数据存储的保护，则可能会在故障转移期间将虚拟机添加到数据存储。如果发生这种情况，请确保在启动故障恢复之前提供这些虚拟机的其他映射信息。要编辑资源映射，请参阅 link:manage.html#manage-replication-plans["管理复制计划"]。



[[steps]]
== 步骤

[role="tabbed-block"]
====
.vCenter
--
.步骤
. 从灾难恢复菜单中，选择*复制计划*。
. 在下拉菜单中，将过滤器设置为 *VMware*。
+
image::site-type-toggle.png[站点类型切换的屏幕截图]

. 确定要回切的复制计划。选择*操作*选项image:../use/icon-horizontal-dots.png["灾难恢复服务中的操作菜单图标"]，将鼠标悬停在*恢复*上，然后选择*故障回切*。
. 选择要从中恢复的数据存储区的快照。选择 *Take snapshot now* 以启动新快照，或 *Select* 从可用快照中进行选择。
+

NOTE: 如果您使用的是防篡改 SnapLock 快照，则必须使用*立即拍摄快照*选项。否则操作将失败。

+
image:failback.png["故障恢复对话框的屏幕截图"]

. 输入 "Failback" 确认操作，然后选择 *Failback*。


要监控作业进度，请在灾难恢复菜单中选择“作业监控”。

--
.Kubernetes
--
. 从灾难恢复菜单中，选择*复制计划*。
. 在下拉菜单中，过滤到 *Kubernetes* 复制计划。
+
image::site-type-toggle.png[站点类型切换的屏幕截图]

. 确定要回切的复制计划。选择*操作*选项image:../use/icon-horizontal-dots.png["灾难恢复服务中的操作菜单图标"]，将鼠标悬停在*恢复*上，然后选择*故障回切*。
. 选择要从中恢复的集群的快照。选择 *Take snapshot now* 以启动新的快照，或 *Use latest snapshot* 以使用最新的成功快照。
. 输入 "Failback" 确认操作，然后选择 *Failback*。


要监控作业进度，请在灾难恢复菜单中选择“作业监控”。

--
