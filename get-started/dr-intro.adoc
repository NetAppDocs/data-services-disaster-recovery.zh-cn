= 了解NetApp Disaster Recovery
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/get-started/


[role="lead"]
云灾难恢复是一种弹性和经济高效的方式，可以保护工作负载免受站点中断和数据损坏事件的影响。NetApp Disaster Recovery 是一种基于云的灾难恢复服务，可为运行 NetApp 存储的 VMware 和 Kubernetes 工作负载自动化灾难恢复工作流程。使用 Disaster Recovery，您可以保护以下工作负载：

* *VMware 工作负载*：基于 NFS 的工作负载以及用于 iSCSI 和 FC 的 VMware vSphere 虚拟机文件系统（VMFS）数据存储。您可以将它们复制到以下目标之一：
+
** Amazon Elastic VMware Service (EVS) with Amazon FSx for NetApp ONTAP。有关详细信息，请参阅 link:../reference/evs-deploy-guide-introduction.html["使用 Amazon Elastic VMware Service 和 Amazon FSx for NetApp ONTAP 进行灾难恢复简介"]。
** AWS 上的 VMware Cloud (VMC) 以及适用Amazon FSx for NetApp ONTAP
** Azure VMware Solution 与 NetApp Cloud Volumes ONTAP (iSCSI)（私有预览）
** Google Cloud VMware Engine (GCVE) 与Google Cloud NetApp Volumes
** 另一个具有 ONTAP 存储的基于 NFS 和/或 VMFS (iSCSI/FC) 的本地 VMware 环境


* *Kubernetes 工作负载*：在您的本地 Kubernetes 集群（包括 OpenShift 虚拟化环境）上运行且使用 Trident 托管的 ONTAP 存储的应用程序。您可以使用 Trident Protect 保护它们，并将它们复制到另一个 Kubernetes 集群。


灾难恢复使用具有集成本机 VMware 编排或 Trident Protect 编排的 ONTAP SnapMirror 技术来保护 VMware 虚拟机及其相关的磁盘操作系统映像和 Kubernetes 应用程序，同时保留 ONTAP 的所有存储效率优势。灾难恢复使用这些技术作为到灾难恢复站点的复制传输。这可以在主站点和辅助站点上实现业界最佳的存储效率（压缩和重复数据删除）。

[[netapp-console]]
== NetApp Console

可通过 NetApp Console 访问灾难恢复。

NetApp Console提供企业级跨本地和云环境的NetApp存储和数据服务的集中管理。需要控制台才能访问和使用NetApp数据服务。作为管理界面，它使您能够从一个界面管理许多存储资源。控制台管理员可以控制企业内所有系统的存储和服务的访问。

开始使用 NetApp Console 无需许可证或订阅，仅在需要在云中部署 Console 代理以确保连接到存储系统或 NetApp 数据服务时才会产生费用。但是，从 Console 访问的一些 NetApp 数据服务是许可或基于订阅的。

详细了解 https://docs.netapp.com/us-en/console-setup-admin/concept-overview.html["NetApp Console"]。



[[benefits-of-using-disaster-recovery]]
== 使用灾难恢复的优势

灾难恢复具有以下优势：

* 简化了 vCenter 和 Kubernetes 集群发现以及通过多个时间点恢复操作恢复应用程序的用户体验。
* 通过降低运营成本来降低总体拥有成本，并能够以最少的资源创建和调整灾难恢复计划。
* 通过虚拟故障转移测试持续做好灾难恢复准备，不会中断运营。您可以定期测试 DR 故障转移计划，而不会影响生产工作负载。
* 通过 IT 环境的动态变化和在灾难恢复计划中解决该问题的能力来更快地实现价值。
* 能够通过ONTAP和 VMware 的后端编排同时管理存储层和虚拟层，而无需部署和维护虚拟服务器设备 (VSA)。
* 使用相同的 ONTAP SnapMirror 技术，并通过 Trident Protect 编排，为 Kubernetes 工作负载提供以应用程序为中心的保护。资源转换允许您在故障转移期间将工作负载调整到恢复环境。
* VMware 的 DR 解决方案可能会占用大量资源。许多 DR 解决方案使用 VSA 在 VMware 虚拟层复制虚拟机，这会消耗更多的计算资源并损失ONTAP宝贵的存储效率。由于灾难恢复使用ONTAP SnapMirror技术，它可以使用我们的永久增量复制模型将数据从生产数据存储复制到 DR 站点，并具有ONTAP的所有本机数据压缩和重复数据删除效率。




[[capabilities-of-disaster-recovery]]
== 灾难恢复功能

灾难恢复可让您充分利用多种 NetApp 技术，以实现以下目标：

* 使用SnapMirror复制将本地生产站点上的 VMware 应用程序复制到云端或本地的灾难恢复远程站点。
* 使用 SnapMirror 复制和 Trident Protect 将 Kubernetes 应用程序复制到目标 Kubernetes 集群。
* 将 VMware 工作负载从原始站点迁移到另一个站点。目前不支持迁移 Kubernetes 工作负载。
* 执行故障转移测试。对于 VMware 工作负载，该服务将创建临时虚拟机。灾难恢复将从所选快照创建一个新 FlexClone 卷，并将由该 FlexClone 卷支持的临时数据存储映射到 ESXi 主机。此过程不会消耗本地 ONTAP 存储或 AWS 中的 FSx for NetApp ONTAP 存储上的额外物理容量。原始源卷不会被修改，即使在灾难恢复期间，副本作业也可以继续。您还可以测试 Kubernetes 工作负载的故障转移，然后清理测试资源。
* 在发生灾难时，根据需要将主站点故障转移到灾难恢复站点。对于 VMware 工作负载，灾难恢复站点可以是搭配 Amazon FSx for NetApp ONTAP 的 VMware Cloud on AWS，或者是搭配 ONTAP 的本地 VMware 环境。对于 Kubernetes 工作负载，您可以故障转移到复制计划中的目标集群。
* 灾难解决后，根据需要从灾难恢复站点故障回复到主站点。
* 将虚拟机、数据存储或 Kubernetes 资源分组到逻辑资源组中，以实现高效管理。
* 对于 Kubernetes 工作负载，请在故障转移期间使用资源转换使应用程序适应恢复环境，并使用快照前或快照后脚本来管理应用程序静默和恢复。

NOTE: 对于 VMware 工作负载，必须在 vSphere Server 中的灾难恢复之外配置 vSphere 服务器。

[[licensing]]
== 许可

您可以使用以下许可证类型：

* 注册即可获得 30 天免费试用。
* 通过 Amazon Web Services (AWS) Marketplace、Azure Marketplace 或 Google Cloud Marketplace 购买按需付费 (PAYGO) 订阅。此许可证允许您购买固定受保护容量许可证，而无需任何长期承诺。
* 自带许可证 (BYOL)，即您从NetApp销售代表处获得的NetApp许可证文件 (NLF)。您可以使用许可证序列号在NetApp Console中激活 BYOL。


所有NetApp数据服务的许可证均通过NetApp Console中的订阅进行管理。设置 BYOL 后，您可以在控制台中看到该服务的有效许可证。

灾难恢复的许可基于受保护 ONTAP 卷上托管的数据量。该服务通过将受保护的虚拟机映射到其 vCenter 数据存储来确定哪些卷应考虑用于许可目的。每个数据存储都托管在 ONTAP 卷或 LUN 上。ONTAP 报告的该卷或 LUN 的已用容量将用于许可确定。对于 Kubernetes 工作负载，许可的计算方式相同。

受保护的卷可以托管多个虚拟机。有些可能不是灾难恢复资源组的一部分。无论如何，该卷或 LUN 上所有虚拟机消耗的存储都将计入许可证最大容量。


NOTE: 当至少有一个 VM 或 Kubernetes 资源具有复制计划时，灾难恢复费用将基于源站点上数据存储的已用容量。故障转移数据存储的容量不包含在容量限额中。对于 BYOL，如果数据超出允许的容量，则在您获得额外的容量许可证或在 NetApp Console 中升级许可证之前，服务中的操作将受到限制。

要了解有关设置灾难恢复许可的详细信息，请参阅 link:../get-started/dr-licensing.html["设置 Disaster Recovery 许可"]。

[[how-disaster-recovery-works]]
== 灾难恢复的工作原理

灾难恢复是 NetApp Console 软件即服务（SaaS）环境中提供的一项服务。灾难恢复可以将从本地站点复制的工作负载恢复到 Amazon FSx for ONTAP 或另一个本地站点。对于 VMware 工作负载，此服务通过将虚拟机注册到 VMware Cloud on AWS 以及直接在 VMware 网络虚拟化和安全平台 NSX-T 上进行网络映射，自动从 SnapMirror 级别进行恢复。此功能包含在所有虚拟机云环境中。

灾难恢复使用 ONTAP SnapMirror 技术，该技术提供高效复制并保留 ONTAP 永久增量快照效率。SnapMirror 复制可确保应用程序一致性快照副本始终同步，并且数据在故障转移后立即可用。

image:dr-architecture-diagram-70-2.png["显示灾难恢复服务基础设施架构的示意图"]

发生灾难时，此服务通过中断 SnapMirror 关系并使目标站点处于活动状态，帮助您恢复其他本地 VMware 环境或 VMC 中的 VMware 虚拟机。

* 该服务还允许您将虚拟机故障恢复到原始源位置。
* 您可以在不中断原始虚拟机的情况下测试灾难恢复故障转移过程。该测试通过创建卷的FlexClone将虚拟机恢复到隔离网络。
* 对于故障转移或测试故障转移过程，您可以选择最新（默认）或选定的快照来恢复虚拟机。


*Kubernetes 工作负载*

对于 Kubernetes 工作负载，灾难恢复使用 Trident Protect 来保护在 Kubernetes 集群上运行的应用程序，包括 OpenShift 虚拟化环境。该服务使用 SnapMirror 来复制 NetApp Trident 在 ONTAP 存储上配置的持久卷。Trident Protect 将 Kubernetes 保护数据保存在 AppVault 中，这是一个云存储目标。发生灾难时，您可以故障转移到目标集群，并且可以在灾难解决后回切到原始源集群。Kubernetes 工作负载的故障转移、回切和故障转移测试遵循与 VMware 工作负载相同的顺序。

*灾难恢复的组成部分*

Disaster Recovery 使用以下组件：

* * NetApp Console*：用于管理灾难恢复计划的用户界面。您可以使用NetApp Console在本地和云环境中创建和管理复制计划、资源组和故障转移操作。
* *控制台代理*：在云托管网络或本地 VMware 环境中运行的轻量级软件组件。它与 NetApp Console 通信，并管理本地环境和灾难恢复站点之间的数据复制。控制台代理安装在您的 VMware 环境中的虚拟机上。对于 Kubernetes 工作负载，控制台代理以相同的方式与您的 Kubernetes 集群进行通信。
* *ONTAP 存储集群*：ONTAP 存储集群是托管 VMware 和 Kubernetes 工作负载的主要存储系统。ONTAP 存储集群为您的灾难恢复计划提供底层存储基础架构。灾难恢复使用 ONTAP 存储 API 来管理 ONTAP 存储集群，例如本地阵列和基于云的解决方案，例如 Amazon FSx for NetApp ONTAP。
* *vCenter 服务器*：VMware vCenter 是您的 VMware 环境的管理服务器。它管理 ESXi 主机及其相关的数据存储。控制台代理与 VMware vCenter 通信，以管理本地环境和灾难恢复站点之间的数据复制。这包括将ONTAP LUN 和卷注册为数据存储、重新配置虚拟机以及启动和停止虚拟机。
* *Kubernetes 集群和 Trident Protect*：对于 Kubernetes 工作负载，Trident Protect 安装并注册在灾难恢复保护的每个 Kubernetes 集群上。当您将 Kubernetes 集群添加为站点时，灾难恢复将指导您在该集群上安装和注册 Trident Protect。


*灾难恢复保护工作流程*

当复制计划分配给资源组时，灾难恢复会对资源组和计划中的所有组件执行发现检查，以确保该计划可以激活。

如果此检查成功，灾难恢复将执行以下初始化步骤：

. 对于目标资源组中的每个虚拟机，确定托管 VMware 数据存储。
. 对于找到的每个 VMware 数据存储库，识别托管ONTAP FlexVol volume或 LUN。
. 对于找到的每个ONTAP卷和 LUN，确定源卷和目标站点中的目标卷之间是否存在现有的SnapMirror关系。
+
.. 如果没有预先存在的SnapMirror关系，请创建任何新的目标卷，并在每个未受保护的源卷之间创建新的SnapMirror关系。
.. 如果存在预先存在的SnapMirror关系，请使用该关系执行所有复制操作。




灾难恢复创建并初始化所有关系后，在每次计划备份时，该服务都会执行以下数据保护步骤：

. 对于标记为“应用程序一致”的每个虚拟机，使用 VMware Tools 将支持的应用程序置于备份状态。
. 为托管受保护的 VMware 数据存储的所有ONTAP卷创建新快照。
. 执行SnapMirror更新操作以将这些快照复制到目标ONTAP集群。
. 确定保留的快照数量是否超过了复制计划中定义的最大快照保留量，并从源卷和目标卷中删除任何多余的快照。




[[supported-protection-targets-and-datastore-types]]
== 支持的保护目标和数据存储类型

*支持的数据存储类型* 灾难恢复支持以下数据存储类型：

* 托管在ONTAP集群上的ONTAP FlexVol卷上的 NFS 数据存储库。
* 使用 iSCSI 或 FC 协议的 VMware vSphere 虚拟机文件系统 (VMFS) 数据存储


对于 Kubernetes 工作负载，NetApp Disaster Recovery 保护通过 NetApp Trident 在 ONTAP 存储上配置的持久卷。

*支持的保护目标*

* AWS 上的 VMware Cloud (VMC) 以及适用Amazon FSx for NetApp ONTAP
* 另一个具有 ONTAP 存储的基于 NFS 的本地 VMware 环境，或本地 FC/iSCSI VMFS 环境
* Amazon Elastic VMware 服务
* Azure VMware Solution 与 NetApp Cloud Volumes ONTAP (iSCSI)（私有预览）
* Google Cloud VMware Engine (GCVE) 与Google Cloud NetApp Volumes
* 运行 Trident 管理的 ONTAP 存储的 Kubernetes 集群（使用 Trident Protect 进行保护）




[[terms-that-might-help-you-with-disaster-recovery]]
== 可以帮助您进行灾难恢复的术语

了解一些与灾难恢复相关的术语可能会对您有所帮助。

* *数据存储*：VMware vCenter 数据容器，它使用文件系统来保存 VMDK 文件。典型的数据存储类型是 NFS、VMFS、vSAN 或 vVol。灾难恢复支持 NFS 和 VMFS 数据存储。每个 VMware 数据存储库都托管在单个ONTAP卷或 LUN 上。灾难恢复支持位于ONTAP集群上的FlexVol卷上托管的 NFS 和 VMFS 数据存储库。
* *复制计划*：一组关于备份频率以及如何处理故障转移事件的规则。计划被分配给一个或多个资源组。
* *恢复点目标 (RPO)*：发生灾难时可接受的最大数据丢失量。  RPO 在复制计划的数据复制频率或复制计划中定义。
* *恢复时间目标（RTO）*：从灾难中恢复可接受的最长时间。RTO 在复制计划中定义，是故障切换到灾难恢复站点并重新启动所有虚拟机或应用程序所需的时间。
* *资源组*：一个逻辑容器，使您能够将多个虚拟机、数据存储库或 Kubernetes 资源作为一个单元进行管理。一个虚拟机一次只能属于一个资源组。您可以为要保护的每个应用程序或工作负载创建一个资源组。
* *站点*：通常与托管一个或多个 vCenter 集群或 Kubernetes 集群以及 ONTAP 存储的物理数据中心或云位置相关联的逻辑容器。
* *AppVault*：对于 Kubernetes 工作负载，Trident Protect 保存 Kubernetes 保护数据的云存储目标。
* *Trident Protect*：灾难恢复用于保护 Kubernetes 应用程序的 NetApp 软件。
